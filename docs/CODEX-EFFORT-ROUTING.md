# Codex reasoning effort 라우팅

이 문서는 Codex 작업을 시작할 때 reasoning effort를 고르는 기준을 정한다. 기본값은 `medium`이며, 비용이 큰 `xhigh`는 기본값으로 쓰지 않는다.

## 기본 원칙

- `medium`을 기본값으로 둔다.
- 단순 조회, 문서 형식 정리, 좁은 범위의 반복 작업은 `low`를 쓴다.
- 여러 파일의 계약, 보안, 배포, 릴리스 판단처럼 실수 비용이 큰 작업은 `high`를 검토한다.
- `xhigh`는 복잡한 장애 분석, 보안 영향 검토, 릴리스 차단 판단처럼 높은 확실성이 필요한 경우에만 명시적으로 선택한다.
- effort를 올리기 전에 읽기 범위와 작업 범위를 먼저 줄인다.
- token, secret, password, `.env`, `secrets/`, `logs/`는 effort와 무관하게 읽거나 출력하지 않는다.

## effort 선택 기준

| effort | 사용 기준 | 예시 |
| --- | --- | --- |
| `low` | 파일 수가 적고 판단보다 기계적 변경이 많은 작업 | 오탈자 수정, 짧은 템플릿 추가, 단일 문서 필드 정리 |
| `medium` | 일반적인 하네스 문서, 스크립트, 큐 작업 | 정책 문서 작성, 배치 스크립트 보완, HANDOFF 갱신 |
| `high` | 여러 문서나 스크립트의 일관성을 맞추고 실패 영향이 큰 작업 | 라우터 설계, 릴리스 절차 검토, 보안 절차 문서화 |
| `xhigh` | 모호성이 크고 잘못된 판단의 비용이 매우 큰 작업 | 사고 원인 분석, 비밀 유출 대응 절차, 릴리스 차단 여부 판단 |

## xhigh 제한

`xhigh`는 자동 루프의 기본값으로 사용하지 않는다. 작업 큐나 프롬프트가 `xhigh`를 요구하면 실행 전에 이유를 한 줄로 남기고, 범위를 줄여 `high`로 처리할 수 있는지 먼저 확인한다.

## 프로필 템플릿

프로필 템플릿은 `codex/profiles/` 아래에 둔다.

- `low.md`: 짧은 확인과 기계적 변경 중심
- `medium.md`: 기본 작업 루프
- `high.md`: 위험과 검증을 더 촘촘히 보는 작업
- `xhigh.md`: 명시적 승인과 범위 축소 검토가 필요한 작업
